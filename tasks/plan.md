# Plan: ace-linting (APE linter + RACE questions, Node and browser)

## Context

Eric wants to write Attempto Controlled English (ACE), lint it, and have RACE answer questions deterministically, in a browser, as an importable package for Node and browser with functions to extend it. The spec is at `/Users/eric/projects/ace-web/docs/spec.md` (draft 2). Decisions that shape this plan:

- New repo `ace-linting` at `/Users/eric/projects/ace-web` (folder name can change). Not yet a git repo.
- APE and RACE run unmodified in the official `swipl-wasm`; in a Web Worker (browser) or worker thread (Node). Build steps allowed.
- v1 = lint + ask + extension API. No autocomplete. Unknown is never turned into "no".
- Lexicon: **Clex is removed** (its COMLEX/LDC origin is unresolved). We build our own clean lexicon with recorded provenance, plus user-added words.
- **Do whatever the licenses require.** GPL-3.0-or-later for the package. Not legal advice; we follow each license's text and flag anything unclear to Eric.

Nothing has been built. The spike gates everything.

## Approach

Treat APE/RACE as black boxes behind a thin Prolog glue file and a typed JS API. All risk sits in whether they run under `swipl-wasm`, so test that first, then build outward in vertical slices (parse, then diagnostics, then ask, then lexicon, then browser).

## Tasks (in order; each ends with its verify step)

**0. Repo and license foundation**
- `git init`; pin submodules `vendor/APE`, `vendor/RACE`; `package.json` named `ace-linting`, license `GPL-3.0-or-later`; `LICENSE` (GPL-3.0 text); `docs/spec.md` committed.
- License inventory file `THIRD_PARTY_LICENSES.md`: for APE (LGPL-3.0-or-later, copyright Attempto Group 2008-2013), RACE (GPL-3.0), Clex (GPL-3.0; read its README for the provenance of its word data and any attribution it requires), SWI-Prolog (BSD-2-Clause) and `swipl-wasm`, plus anything `swipl-wasm` bundles (e.g. zlib). Read each repo's actual LICENSE file; do not rely on GitHub's detected label (APE showed "NOASSERTION").
- Verify: every vendored or bundled component has a license file copied into the package, and the inventory lists name, version/commit, license, copyright, and where its text lives.

**1. Spike (gate; script `scripts/spike.mjs`)**
- In Node with `swipl-wasm`: load APE, parse "Every customer inserts a card." -> DRS + paraphrase; parse a bad sentence -> messages with sentence/token position and offending token; load RACE and answer "Who inserts a card?"; then repeat in a browser Web Worker.
- Record: load time, per-sentence parse time, wasm and image size (raw and gzip/brotli), whether `clib`/`sgml`/`http` were needed.
- Verify: results written to `docs/spike-results.md`. If APE or RACE cannot run without native packages, stop and revise the spec (patch around, server, or JS port); do not proceed.

**2. Tokenizer and diagnostics mapping** (`src/diagnostics.js`, `src/tokenize.js`)
- Split text into sentences with character offsets; mirror APE's tokenizer; map APE message (scope, sentence N, token M, bad token, suggestion) to `{severity, code, message, range, sentence}`; fall back to whole-sentence range when the token cross-check fails.
- Verify: fixture tests (`node --test`) for valid text, each message scope (character/word/sentence/anaphor/pronoun), multi-sentence, quotes, non-ASCII, missing final period.

**3. Lint API** (`src/index.js`, `src/worker.js`)
- `createAce()`, `ace.lint(text)`, `dispose()`; worker boundary carries plain objects only; sentence cache keyed by hash of text up to that sentence; debounce helper for editors.
- Verify: tests for cache hits after an edit to the last sentence; lint of a long note stays within the spike-measured latency target.

**4. Ask API with RACE** (`prolog/race_glue.pl`, `src/ask.js`)
- `ace.ask({text, question, timeoutMs})` -> `{status: "answered"|"unknown"|"timeout", answers, proof}`; relevance selection of sentences before RACE, retry with full text on "unknown"; terminate and restart worker on timeout.
- Verify: fixtures for yes/no, who/what, how many, which, and cases where the answer is unknown (must stay "unknown"); a deliberately runaway query hits the timeout and the next call still works.

**5. Clean custom lexicon and user words** (`lexicon/`, `src/lexicon.ts`)
- Build our own lexicon in APE's lexicon format, loaded through its user-lexicon mechanism. Sources: words we write ourselves (a core vocabulary for project notes: people, tasks, dates, ownership, dependencies), plus any outside word list only after its license is read and recorded. Inflected forms are generated by a script from base words and classes, not hand-typed.
- `lexicon/PROVENANCE.md` records, for every source, where it came from, its license, and what we took. No COMLEX-derived data.
- `lexicon.add/remove` for users sits on top, with conflict checks (user overrides ours and APE's built-in, with a warning).
- Verify: adding a noun makes a failing sentence pass; every word in our lexicon parses in a sentence of its class; `PROVENANCE.md` covers every entry; lexicon size and load time recorded.

**6. Extension hooks** (`src/extensions.js`)
- `ace.use({name, afterParse})` can add diagnostics but cannot override what APE rejected. Ship one example plugin as the template: the semantic type check from the "Types" section.
- Verify: plugin tests, including a plugin that throws (must not break lint).

**7. Browser package and demo** (`demo/`)
- Bundle worker + wasm + image for browsers; Node import works directly; demo page with debounced squiggles and a question box; confirm no network requests after load (apart from the lazy image/Clex fetches).
- Verify: same fixtures pass in a real browser; demo in the built-in browser shows squiggles and an answer; DevTools network tab shows nothing sent with user text.

**8. License compliance and release prep**
- Ensure the published package contains: `LICENSE`, `THIRD_PARTY_LICENSES.md`, each component's license text, per-file source headers on our files, and the corresponding source (repo tagged to match each published version; vendored submodules pinned). Add a README "Licensing" section that states the combined license and links to source.
- `npm publish --dry-run` to inspect package contents; check the tarball includes the notices and the size is within budget.
- Flag to Eric, not decide: any lexicon source with unclear terms, or any `swipl-wasm` bundled component without a clear license.

## Distribution change (decided after the Clex licensing finding)

We ship none of APE or RACE. A fetch-and-verify step replaces any bundling:
- `scripts/upstream.json` lists each upstream (repo, pinned commit, file list, sha256 per file).
- Node: `ace-linting fetch` (also run on first `createAce()` if missing) downloads the pinned files into a local cache and verifies hashes.
- Browser: first load fetches the same pinned files from a commit-pinned CDN URL (jsDelivr's GitHub mirror), verifies hashes with `crypto.subtle`, writes them into the Prolog virtual file system, compiles the grammar (about 230 ms), and caches in IndexedDB. No prebuilt image containing their code is published, and the published package and any hosted demo contain none of their files.
- `vendor/` submodules are development only and excluded from the package (`files` whitelist).
- Our own lexicon is ours to ship (we write it or verify each source's license).
- Affects tasks 7 and 8: no bundling of their code; the demo fetches from upstream; the publish check asserts the tarball contains none of their files.

## Types (added after review)

Yes, two kinds, both in scope:

1. **TypeScript types for every output (v1, from task 2 onward).** The source is written in TypeScript (build steps are allowed), and the types are a first-class, exported part of the package: `import type { Diagnostic, AskResult } from "ace-linting"`, plus a `ace-linting/types` entry for types only. `package.json` `exports` lists `types` for both the Node and browser entries. A type-level test file (`tests/types.test-d.ts`, checked with `tsc --noEmit` in `npm test`) pins the exact shape of each output, so a change to an output breaks the build. The spec's "JSDoc types" line is updated to match (a spec edit, done when plan mode ends). Defined once, used by lint, ask, lexicon and plugins:
   - `Diagnostic { severity, code, message, range, sentence, suggestion? }`, where `code` is a union of APE's message scopes (`character | word | sentence | anaphor | pronoun`) plus our own codes.
   - `AskResult` (`status: "answered" | "unknown" | "timeout"`, `answers`, `proof`) and `AskOptions`.
   - `LexiconEntry` as a union per word class (noun, verb, adjective, adverb, preposition, proper name) with their forms and gender.
   - `Plugin`, `AceOptions`, and a typed `Drs` JSON shape, so no Prolog terms leak out of the worker.
   - Outputs are discriminated unions where it helps (for example `AskResult` on `status`), so callers get exhaustive checks. The worker boundary validates the shape before returning it, so a Prolog-side surprise becomes a typed error instead of a malformed object.
2. **Semantic types (the "a coffee can't execute" check).** An optional plugin, not part of core, because ACE itself has no word types. It would take a small JSON schema (noun -> type, verb -> accepted subject and object types, as in `english-ast`'s `src/schema/schema.json`) and add diagnostics after APE accepts a sentence. It becomes task 6's example plugin, so the plugin API is proven by a real use. Whether to ship it in core is a later decision.

## Risks to watch

- APE/RACE may need Prolog packages `swipl-wasm` lacks (spike item 1).
- Token-to-character mapping may be unreliable on unusual punctuation (fallback: whole-sentence ranges).
- RACE may run away on large texts (relevance selection plus terminable worker).
- A clean lexicon takes real work to make useful; start from a small domain core and grow it.
- License provenance of any outside word list needs reading, not assuming.
